# FDE 客户演示方案：流程图 与 本体 的关系、区别与工具选型

> 交付形态：单文件 HTML 翻页 Deck（对客户投屏用）
> 口径：**纯通用 FDE 方法论**，不出现本插件/任何具体产品名
> 听众：业务高管/决策者 + 业务骨干/流程 Owner + IT/架构负责人（同场或分场）
> 状态：待批准

---

## 0. 一句话结论

**流程图回答"事情按什么顺序走"，本体回答"这件事里有什么、彼此怎么约束"。**
FDE 的交付不是"一张好看的图"或"一张漂亮的图谱"，而是**能走的图 + 能算的模型 + 能点的应用**三件套；
一套资产要能被切成三种讲法，分别喂给高管、流程 Owner 和 IT 架构。

## 3. 内容主线（四个核心论点，全篇围绕）

1. **不是二选一，是两层**：流程图是"动词序列"，本体是"名词与约束"；流程跑在本体之上。
2. **三级流程资产必须分开讲**：流程框架地图（分类/盘点）≠ 流程图（沟通/共识）≠ 流程模型（可执行编排）。
   混为一谈是 FDE 最常见的灾难（客户以为"图就是系统"）。
3. **关联只有 5 个锚点**：活动↔行为、泳道↔角色、分支条件↔规则、表单/单据↔对象、产出↔查询报表。
   锚点打通 → 图和模型双向可追溯；锚点没打通 → 图库化、模型孤儿。
4. **工具分层决定客户体验**：白板（客户说）→ 流程图（客户认）→ 本体（客户裁决口径）→ 应用原型（客户点）→ 看板/沙盘（客户拿走汇报）。
   每一层都必须有"客户可操作物"，否则演示即巅峰。

## 5. 关键图示规范（三张必须画对的图）

### 5.1 关系大图（第 6 页）
- 上层（横向）：`活动 A → 活动 B → 活动 C`，其中 B 后接判定菱形分两支；泳道用底色区分角色。
- 下层（横向）：`对象层`（实体方块 + 关系线）、`规则层`（约束标签）、`角色层`（人形点）。
- 中间 5 条竖线：活动→行为（虚线）、泳道→角色（点线）、分支→规则（实线带条件标签）、表单→对象（实线）、产出→报表（虚线）。
- 视觉原则：**下层实、上层虚**；表达"流程是投影，本体是地基"。

### 5.2 三级流程资产（第 7 页）
- 同一件事的三张缩略图并排：分类树（L1–L5）、泳道流程图、节点图（含角色/规则引用角标）。
- 下方一条寿命条：框架地图（年级）→ 流程图（月级）→ 流程模型（随变更同步）。

### 5.3 覆盖度热力图（第 11 页）
- 纵轴：对象（8–10 个），横轴：流程活动（8–10 个），格子三态（缺对象/缺角色/完整）；
- 右侧给"缺口 Top 3"清单，直接对应下一步访谈题目——把图变成行动。

## 6. 视觉与实现约定

- 使用 `html-deck` 技能生成，遵循其版式与动画规范；不引入外部 CDN/font。
- 配色：墨蓝 `#0F2A44`（主）、暖琥珀 `#E8A33D`（强调/流程层）、青灰 `#5B7C8D`（本体层）、纸白 `#F7F5F0`（底）；避免纯黑纯白。
- 字体：`system-ui, "PingFang SC", "Microsoft YaHei", sans-serif`；标题 700，正文 400；正文最小 18px（投屏可读）。
- 动效：页切换 fade+8px 位移；图中元素逐条淡入（≤300ms/条）；不做视差、不做循环动画。
- 每页强制：一个论点 + 一张图；文字不超过 80 字/页（脚本页除外）。
- 术语页（4/5/7/12）允许密集，其余必须留白。

## 7. 假设与决策

| 项 | 决策 | 理由 |
|---|---|---|
| 是否绑定具体产品/页签 | 不绑定 | 用户明确选"纯通用 FDE 方法论" |
| 是否包含行业案例 | 用匿名化的通用案例（"某制造企业的合同到回款"） | 三类听众都能代入，且不泄露客户 |
| 单 Deck 还是三 Deck | 单 Deck，用分节页 + 脚本页覆盖三类听众 | 客户现场通常混场；一份 Deck 便于复用 |
| 是否含真实演示系统 | 否，只讲方法 + 演示编排 | 本次范围是"方案"，落地系统另议 |
| 是否产出配套 Markdown 讲稿 | 否，脚本内容直接做进第 19–21 页 | 避免多份文件不同步 |

## 8. 验收标准

1. 单文件 HTML，双击即开，无外链请求（断网可用）。
2. 22 页齐全，←/→/空格 翻页正常，页码正确，`F` 全屏可用。
3. 1280×720 与 1920×1080 下无文字溢出、无遮挡；正文 ≥18px。
4. 三张大图（§5）在投影下 3 米可辨识（字号/线宽达标）。
5. `Ctrl+P` 输出 22 页横向 PDF，布局不塌。
6. 全文无产品名/插件名/内部页签名。
7. 第 19–21 页脚本可直接照读，每页含"这句话为什么这么说"的一句话注解。

## 9. 不做的事

- 不修改 `src/` 任何代码，不动插件功能。
- 不做动画大片、不做滚动叙事长页（这是翻页 Deck，不是网页报告）。
- 不覆盖具体行业的合规条款细节。
- 不承诺任何量化收益数字（Deck 中只给"如何度量"，不给虚构百分比）。
